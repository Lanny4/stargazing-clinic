# Stargazing — сайт косметологічної клініки

Готовий навчальний проєкт до **лабораторної роботи №1 «Ознайомлення з середовищем та базовими інструментами»**.

## 1. Мета

Ознайомитися з технологіями веброзробки, встановленням робочого середовища, створенням вебсторінки та публікацією статичного сайту.

## 2. Використані технології

| Технологія | Для чого використовується у веброзробці | У цьому проєкті |
|---|---|---|
| HTML5 | Структура та семантика сторінки | `index.html`: шапка, секції, картки, FAQ, форма, підвал |
| CSS3 | Оформлення і адаптивність | `styles.css`: кольори, шрифти, сітки, медіазапити |
| JavaScript | Інтерактивність на стороні браузера | `script.js`: меню, вибір послуги, перевірка форми, дата |
| Ruby | Серверна мова для бекенду (наприклад, Rails) | Не потрібна для статичного прототипу |
| Python | Мова бекенду / локальний сервер | `python3 -m http.server 5500` для локального перегляду |
| Node.js | Запуск JavaScript поза браузером, сервер і збірка | Оглянуто теоретично, у цьому проєкті не потрібен |
| REST API | Інтерфейс обміну даними між клієнтом і сервером через HTTP | Оглянуто теоретично; реального API у демосайті немає |

**Важливо:** сайт є статичним прототипом. Форма запису перевіряє поля у браузері, але не надсилає дані, не створює реальних заявок і нічого не зберігає.

## 3. Структура проєкту

```text
stargazing-clinic/
├── index.html         # HTML5-структура
├── styles.css         # Стилі та адаптивність
├── script.js          # Інтерактивні функції
├── assets/
│   ├── favicon.svg    # Іконка вкладки
│   ├── hero-art.svg   # Резервна ілюстрація для першого екрана
│   └── clinic-art.svg # Резервна ілюстрація для розділу «Про нас»
├── .nojekyll          # Публікація статичних файлів GitHub Pages
└── README.md          # Опис та інструкції
```

Для двох основних блоків використані зовнішні фото з Unsplash (за наявності інтернету); якщо фото недоступне, завантажується локальна SVG-ілюстрація. Усі тексти, назва і ціни — демонстраційні.

## 4. Як запустити у VS Code та WSL Ubuntu

1. Відкрий VS Code і вибери **File → Open Folder** (папка `stargazing-clinic`). Якщо працюєш через WSL, можна відкрити папку в терміналі командою `code .`.
2. Відкрий вбудований термінал VS Code (Terminal → New Terminal).
3. Переконайся, що доступний Python: `python3 --version`.
4. Перейди до папки, в якій лежить `index.html`, і запусти:

   ```bash
   python3 -m http.server 5500
   ```

5. Відкрий браузер за адресою **http://localhost:5500/**.
6. Перевір навігацію, картки послуг, FAQ, форму і вигляд на телефоні (DevTools → Toggle device toolbar).
7. Зупинити сервер: **Ctrl+C**.

Альтернатива: розширення **Live Server** у VS Code, кнопка **Go Live**.

## 5. Основні команди Git

Створи **порожній** публічний репозиторій `stargazing-clinic` на https://github.com/new (без README, `.gitignore` і ліцензії, бо файли вже готові). У терміналі проєкту:

```bash
git --version
git init
git add .
git commit -m "Add Stargazing clinic website"
git branch -M main
git remote add origin https://github.com/USERNAME/stargazing-clinic.git
git push -u origin main
```

Заміни `USERNAME` на свій нік GitHub. Якщо Git попросить ім'я та email, виконай `git config --global user.name "Ім'я"` і `git config --global user.email "твій-email"`, після чого повтори `git commit`. GitHub може попросити авторизуватися (пароль акаунта не використовується як пароль для HTTPS Git-операцій).

## 6. Публікація GitHub Pages

1. У репозиторії натисни **Settings → Pages**.
2. **Build and deployment → Source:** вибери **Deploy from a branch**.
3. **Branch:** `main`; папка `/(root)`; натисни **Save**.
4. Після завершення розгортання натисни **Visit site**.

Очікувана адреса: `https://USERNAME.github.io/stargazing-clinic/` (замінити `USERNAME`). Публікація може тривати до 10 хвилин. GitHub Pages підтримує статичні файли, але не виконує Python/Ruby як бекенд.

Джерело: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 7. Що перевірити під час захисту

| Перевірка | Дія | Очікуваний результат |
|---|---|---|
| Структура | Відкрити `index.html` | Є семантичні елементи `header`, `main`, `section`, `footer`, `form` |
| Оформлення | Відкрити головну сторінку | Є кольори, типографіка, картки послуг |
| Адаптивність | Зменшити ширину в DevTools | Блоки перебудовуються, меню стає мобільним |
| Навігація | Натиснути «Послуги» | Прокрутка до секції послуг |
| Вибір послуги | Натиснути «Обрати процедуру» | У формі обрано відповідну процедуру |
| Валідація | Надіслати порожню форму | Браузер підказує, які поля обов'язкові |
| Деморезультат | Заповнити коректно і натиснути кнопку | З'являється повідомлення, що перевірка успішна, але запис не створено |
| Git/GitHub | Відкрити репозиторій | Файли сайту доступні у GitHub |
| Публікація | Перейти на адресу GitHub Pages | Сайт відкривається з інтернету |

## 8. Що таке REST API (коротко)

**REST API** дозволяє клієнтському застосунку отримувати та надсилати дані серверу через HTTP. Наприклад, у майбутньому сайт міг би взаємодіяти із сервером так:

- `GET /api/services` — отримати список послуг;
- `POST /api/appointments` — надіслати запит на запис;
- `GET /api/appointments/15` — отримати відомості про конкретний запис (лише після належної авторизації).

Для реального онлайн-запису потрібні бекенд, база даних, перевірка введення на сервері та захист персональних даних. Це виходить за межі лабораторної роботи №1.

Розроблено адаптивний демонстраційний сайт косметологічної клініки Stargazing із навігацією, блоком послуг, FAQ та інтерактивною формою.
